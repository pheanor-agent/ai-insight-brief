확장 마켓의 신뢰는 어디에서 끊겼나

정도윤 · 가상 필자수록 2026-11-16

← 이 해설이 포함된 11월 16일 리포트

소식 · 원문 발표 2026-11-13 · 사이트 수록 2026-11-16 · 해설 본문 예상 읽기 약 4분

Cursor의 11월 13일 사고 보고서에 따르면, 10월 29일 악성 Claude Code 확장 사본 두 버전이 Cursor의 VS Code 확장 마켓플레이스 캐시에 올라갔습니다. 공격자는 Anthropic의 게시 권한을 얻지 않았고, Open VSX에도 해당 사본은 없었습니다. Cursor가 설명한 경로는 Fireworks에서 노출된 Cursor 발급 접근 키에서 시작합니다. 이 키로 공격자는 Cursor가 Fireworks와 공유하던 읽기 전용 버킷을 복사했고, 그 안에서 다른 내부 시스템으로 이어지는 자격증명을 얻었습니다.

Cursor의 보고를 따라가면 권한은 여러 단계를 거쳤습니다. 버킷에 있던 코딩 에이전트 트레이스 일부에는 삭제되지 않은 자격증명이 남아 있었고, 이를 이용해 접근한 내부 SaaS 도구에서 추가 자격증명을 얻었습니다. 공격자는 그 자격증명으로 확장 마켓플레이스 캐시에 악성 버전을 직접 올렸습니다. 따라서 확인된 사고 경로는 한 외부 키가 곧바로 마켓에 파일을 쓴 이야기가 아닙니다. 데이터 보관, 내부 도구 접근, 배포 캐시 쓰기 사이에 권한과 비밀정보가 연결돼 있었습니다. 이 설명은 Cursor 자체 사고 보고에 근거하며 독립 감사로 확인된 경로는 아닙니다.

회사는 버킷에 주로 2025년 코딩 에이전트 트레이스가 있었고, Privacy Mode를 사용하지 않은 세션 일부에는 삭제되지 않은 자격증명이 남았다고 밝혔습니다. Cursor는 API 자격증명이 노출된 고객을 0.01% 미만, 코딩 트레이스가 노출된 사용자를 0.05% 미만으로 추산했습니다. 공격자는 내부 SaaS 도구를 통해 비운영 소스 저장소 일부, 지원 문의와 이메일, 제품 사용 지표, 일부 대화 요약, 고객이 지원팀에 보낸 자격증명에 접근했다고 회사는 보고했습니다. 이어 확장 버전 2.1.312와 2.1.313을 캐시에 올렸습니다.

회사는 해당 버전을 최대 5,000명이 요청했을 수 있다고 밝혔습니다. 이 수치는 감염자 수가 아닙니다. 요청은 설치나 실행을 뜻하지 않으며, 공개된 정보만으로 실제 설치 규모나 백도어가 작동한 기기 수도 알 수 없습니다. 악성 버전은 약 11시간 노출된 뒤 제거됐습니다. Cursor는 마켓플레이스를 내리고, 공격자 서버를 호스팅한 클라우드 사업자와 함께 서버도 중단했다고 밝혔습니다. BleepingComputer는 악성 확장이 영구 SSH 백도어를 설치하려 했다고 보도했지만, SSH가 이미 켜져 있지 않은 일부 Windows·macOS에서는 코드 오류로 작동하지 않았을 가능성도 전했습니다. 모든 기기에서 같은 결과가 났다고 볼 근거는 없습니다.

이 사고에서 확인할 지점은 확장 이름이나 마켓의 외관만이 아닙니다. 팀은 게시자와 버전, 출처, 설치 경로를 고정하고 민감한 확장을 조직이 승인한 공급 경로와 대조할 수 있습니다. 다만 그 확인은 파일을 어디서 받았는지를 좁힐 뿐, 상류 공급망에서 배포 캐시 쓰기 권한이 어떻게 생겼는지까지 보증하지는 않습니다. Cursor는 Fireworks로 보내던 추론 트래픽을 이전하고, 키를 비활성화하고 노출된 자격증명을 회전했으며, 다른 확장의 진위를 확인하고 마켓을 재구축했다고 밝혔습니다. 마지막 공격 활동은 11월 1일 차단됐고 사건은 통제됐다는 설명도 회사가 내놓았습니다. 회사는 운영 인프라, 공식 앱 릴리스, 고객 코드 저장소, Privacy Mode 사용자 데이터는 영향받지 않았다고 했습니다. 개발팀이 물어야 할 것은 “확장 파일이 마켓에 있나”에서 끝나지 않습니다. 그 파일을 올릴 권한은 어떤 경로로 만들어졌고, 그 경로에서 얻은 자격증명이 어디까지 다시 쓰일 수 있었는지가 핵심입니다.
